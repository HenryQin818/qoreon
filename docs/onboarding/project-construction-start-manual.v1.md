# 项目建设启动手册 v1

本文给出公开版项目启动的最小治理路径。所有路径均以仓库根目录或用户显式配置的协作目录为基准，不依赖特定电脑、账户或私有目录。

## 1. 启动目标

一个可接管的新项目至少需要：项目配置、通道结构、Agent 身份、会话绑定、任务入口和可复核的初始化结果。

## 2. 推荐顺序

1. 明确项目目标、边界和验收条件。
2. 创建项目目录与任务目录。
3. 在公开配置中登记项目及通道。
4. 为正式派发通道创建主会话。
5. 将会话身份写入项目会话真源。
6. 生成可配置协作目录中的通讯录视图。
7. 执行可见性、唯一主会话和消息回执验证。

协作目录由项目配置显式提供；示例项目默认使用仓内目录。通讯录是协作索引，不替代 live session 真源。

## 3. 通道治理字段

- `structure_layer`：标识现役主干、待启用或历史兼容层。
- `requires_primary`：标识是否要求唯一主会话。
- `formal_dispatch_entry`：标识是否允许作为正式派发入口。

正式派发通道默认只有一条主会话。待启用通道和历史兼容层不应自动创建主会话。

## 4. AGENTS.md 工程理念基线

新项目根级 `AGENTS.md` 应包含抽象工程理念；通道级规则继承根级理念，具体技术栈、命令和验收步骤由项目任务补全。

1. 生产级交付：默认按生产项目标准开展工作，不交付临时拼凑或仅为演示成立的中间态。
2. 改动即清理：新增、替换、重构时同步清理被取代内容、死代码和无效配置。
3. 结构干净：保持目录、职责、依赖和数据流清晰。
4. 真源优先：结论以项目认可的真源和可复核证据为准。
5. 自验闭环：完成前执行与任务级别匹配的验证，无法验证时明确标注。
6. 复用优先：同类能力、组件、样式和规则优先抽象复用。

通道级可使用以下继承句：

> 本通道所有方案、实现、验收和回执均需遵循项目根 AGENTS.md 的工程理念基线；具体执行细则由当前任务、责任位和验收口径补全。

## 5. 最小验收清单

1. 项目配置可读取。
2. 第一批正式通道目录已生成。
3. 正式派发通道存在唯一主会话。
4. 会话身份、工作目录和项目绑定可复核。
5. 通讯录视图由配置和会话真源生成。
6. 至少一个通道完成消息发送与回执闭环。
7. 现役、待启用和历史兼容通道边界清晰。
